## [0.1.0] — 2026-11-25

Первый публичный релиз.

### Added

**Диалоги и состояние**
- `defineDialog` / `registerDialog`: диалог — группа окон со своим состоянием и своим стеком навигации.
- Сессия хранит стек фреймов; `ctx.data` — состояние активного диалога, `ctx.frame` — его окно, история и `startData`.
- Состояние разных диалогов изолировано друг от друга.
- `entry` по умолчанию — первое окно массива; явный `entry` проверяется и типами, и рантаймом.
- `registeredDialogIds()` для стартовой диагностики проводки.

**Навигация**
- `goTo` (с опцией `pushHistory`), `goBack`, `show`.
- Вложенные диалоги: `startDialog` кладёт фрейм поверх, `done(result)` возвращает результат родительскому окну через статичный хук `onDialogResult`.
- `resetDialog` (очистка стека, то же сообщение) и `restart` (то же + снятие старой клавиатуры и новое сообщение).

**Ввод**
- Конвейер `raw → formatter → inputSchema → onInput(value)`.
- Тип значения выводится из Zod-схемы; хелпер `defineWindow` для окон с вводом.
- `InputValidationError` — своё сообщение об ошибке из форматтера.
- Ошибка форматтера трактуется как ошибка валидации, а не сбой диалога.
- Ошибка ввода живёт до ухода с окна и переживает перерисовки; `render` остаётся чистым.

**Guard'ы**
- Чистый предикат доступа на двух гейтах: перед обработкой ввода/экшена и перед рендером.
- Редирект не засоряет историю; `maxNavigationDepth` защищает от циклов.

**Медиа**
- Окна `photo`, `document`, `video`, `animation` наряду с текстовыми.
- Текст ↔ медиа заменяются с удалением старого сообщения, медиа → медиа редактируется на месте.
- Предупреждение в лог при превышении лимита `caption` (1024 символа).

**i18n и разметка**
- Словари с перекрытием встроенных core-подписей (ru/en), запасной язык.
- Однопроходная подстановка параметров с автоэкранированием под `parseMode` (HTML по умолчанию, поддержан MarkdownV2).
- Экспорт `escapeHtml` / `escapeMarkdownV2` для ручной сборки текста.

**Надёжность**
- Ответ на callback query ровно один раз за апдейт.
- `message is not modified` не порождает дублей сообщения.
- Зарезервированный namespace `__dm:` и валидация `callback_data` (1–64 байта UTF-8) при регистрации и рендере.
- Лимиты `maxHistory`, `maxDialogDepth`, `maxNavigationDepth`.
- Рекурсивная защита `onError`, локализованный запасной ответ.
- В логи пишется длина пользовательского ввода, а не сам текст.

**Интеграция**
- Инъекция логгера (`DialogLogger`), по умолчанию no-op; ядро не зависит от логгера приложения.
- Нулевые runtime-зависимости; `grammy` и `zod` — peer-зависимости.
- ESM-сборка с `.d.ts` и самодостаточными source maps.

**Прочее**
- Пример бота (`examples/bot`) и компилируемый quickstart (`examples/quickstart`), оба под `typecheck`.
- 35 тестов ядра на Vitest с перехватом Telegram API через transformer.
